# 0002. Use Podman Quadlets instead of Docker Compose

- Status: accepted
- Date: 2026-11-09

## Context

The services (Authentik, cloudflared, Stalwart, ...) currently run as Docker Compose stacks that grew over time and are
hard to reproduce. The homelab is being rebuilt as code with Ansible, so the runtime has to fit well into automation.

Requirements:

- Services start at boot, restart on failure, and log somewhere central.
- The setup is declarative and easy to template with Ansible.
- Containers should not run as root unless they have to.
- Images update without manual work.
- No high-availability needs: nothing has to survive a host failure. Authentik, the most critical service, runs
  fine on a single host.

## Options considered

1. **Keep Docker Compose.** Familiar and well documented, but it depends on the root-running `dockerd`, and boot
   ordering and logs live outside systemd. Updates need an extra tool such as Watchtower.
2. **Podman with `podman-compose`.** Reuses the compose files, but it's a community translation layer with gaps, and
   it doesn't give systemd integration.
3. **Podman Quadlets.** Each container, network and volume is a small unit file that systemd turns into a service.
   No daemon, rootless by default, logs in journald, updates built in via `podman auto-update`.
4. **Kubernetes (k3s or similar).** Powerful, but the HA and scheduling it offers solves problems this homelab doesn't
   have, at a large cost in complexity.

## Decision

Services run as **Podman Quadlets**, **rootless by default**, deployed by Ansible:

- Quadlet files (`.container`, `.network`, `.volume`) are generated by the roles in the Ansible collection
  (see [0004](0004-ansible-in-a-separate-collection-repo.md)), not written by hand.
- Each service runs as a dedicated user with lingering enabled, from `~/.config/containers/systemd/`.
- Rootful Quadlets (`/etc/containers/systemd/`) are used only where rootless is impractical, and each such case is
  documented.
- Images use `AutoUpdate=registry`. `podman-auto-update.timer` pulls new versions and rolls back if the service
  fails to start.
- Kubernetes is explicitly out of scope until there is a real HA requirement.

Game servers are the exception, see [0003](0003-game-servers-stay-on-docker.md).

## Consequences

- **Version requirement:** Quadlets need Podman 4.4 or newer. Debian 12 ships 4.3, so Debian hosts need Debian 13 or
  newer. Every host must be checked before migrating.
- **Rootless details to handle:**
  - `loginctl enable-linger` for each service user
  - subuid/subgid ranges
  - ports below 1024 need a higher published port or `net.ipv4.ip_unprivileged_port_start`, e.g. LDAPS on 636
- **Authentik outposts** expect a Docker socket. `podman.socket` has to be enabled and passed in.
- Container-to-container DNS only works on user-defined networks, so related containers share a `.network` file.
- Operations move to systemd tooling: `systemctl --user status`, `journalctl --user -u`.
- The existing compose files have to be rewritten as Quadlets, one service at a time. Docker and Podman run side by
  side during the migration.
